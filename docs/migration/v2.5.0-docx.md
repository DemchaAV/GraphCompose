# Migrating to 2.5 — the Word export

GraphCompose 2.5 makes PDF, PowerPoint and Word three full outputs of one document. For
Word that means a different export: in 2.4 `DocxSemanticBackend` walked the document without
laying it out and let Word choose every line height and column width; in 2.5 it asks for the
compiled layout and writes the page the engine laid out, as a document an editor can change.
Word still paginates it and reflows it after an edit.

This note covers what a 2.4 caller of the Word export needs to know. The
[`v2.5.0` section of the changelog](../../CHANGELOG.md) carries every change in detail, and the
[backend capability matrix](../architecture/backend-capability-matrix.md) says per capability
what the Word output carries. PDF and PowerPoint callers have nothing to change.

## TL;DR — your code compiles and runs unchanged

`session.export(new DocxSemanticBackend())` stays the Stable path. Everything new is
additive and `@Beta` — the export report, the backend builder, the provider, `buildDocx` and its
siblings, and the section export — and the published constructors of `SemanticExportContext`
and `ShapeNode` are kept.

## What changes in the file

Code that reads an exported DOCX back should expect:

- a list as Word numbering (`w:numPr`) rather than marker text;
- body text that restates the `Normal` style without its own font, size or colour;
- a chart as a Word chart part, its numbers in an embedded workbook, rather than a table — except a
  chart sharing a table cell with other drawings, or in a table composed in a cell, which is still
  its data table;
- drawings — shapes, paths, barcodes — as anchored DrawingML shapes;
- Word's own rule, a paragraph a reader moves or deletes, only for a horizontal line or a divider
  (`addLine`, `addDivider`, `ModuleBuilder.divider`, `DocumentDsl.divider`) of a plain fill, no
  thicker than Word's thickest border (12pt) and in the flow; any other box, however thin, is a
  drawing;
- tables of a fixed layout with the page's column widths;
- a band of one-line captions as one paragraph, its parts at tab stops;
- a spacer as a paragraph a tenth of a point tall with the rest of its height as spacing;
- a page zone as the band the page lays out, on the pages its `appliesTo` picks where Word has such a
  header or footer, rather than one line of runs on every page;
- headers and footers for text headers and footers and page backgrounds, which 2.4 ignored;
- the faces the document is set in, embedded — a family's four faces are about 2.5 MB. The
  standard PDF faces are never embedded, and a face whose terms forbid embedding, or allow it for
  reading and printing only, is named in the report and not shipped.

A watermark, protection options and viewer preferences are still not written; the report names them.

## What the export tells you

- **The report names every loss.** Pass a sink — `new DocxSemanticBackend(report -> ...)` or
  `DocxSemanticBackend.builder().reportSink(...)` — to receive a `DocxExportReport` listing every
  node the export dropped (`DROPPED`) or wrote as the nearest thing Word has (`APPROXIMATED`), with
  the authored node's path.
- **The log says less.** A chart no longer logs `docx.export.chart-fallback` unless it is written as
  its data table, lines, shapes and barcodes are drawn rather than dropped with a warning, and
  `docx.zone.pagePredicate` is logged only for a zone predicate Word has no header or footer for. New
  warnings name a face not embedded, a container's corner radius a table cell cannot draw, and an
  inline chip whose shape is lost. The log still names a kind of loss once per export; the report
  names every node.

## Things to check

- **Exporting costs a layout pass.** The export compiles the layout a PDF render runs and reads each
  image a second time. A document the engine cannot lay out still exports, with less of the page's
  geometry, and the report's `measured geometry` note gives the reason.
- **Byte comparisons need the deterministic backend.** Pass
  `DocxSemanticBackend.builder().deterministic(true).build()` to `session.export(...)`: `buildDocx`,
  `writeDocx` and `toDocxBytes` take a backend without the option and write the current date.
  Compare bytes produced on one platform; across platforms Apache POI's line separator differs.
- **`graph-compose-render-docx` is enough on its own.** It now brings `graph-compose-render-pdf`,
  which a session needs to open; with 2.4, core and render-docx alone failed at `create()`.
- **Two narrow source breaks for code that takes records apart.** `SemanticExportContext` has six
  components, and `ShapeNode` gained `divider`: a record pattern that destructures either in its 2.4
  form no longer compiles. A `SemanticExportContext`'s `equals`, `hashCode` and `toString` now walk
  the layout it carries.
